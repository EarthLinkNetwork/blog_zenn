# 機密かどうかを AI に聞く前に、自前の regex で伏せる ── 判断モデルを比べた結果と、本番への組み込み

![機密かどうかを AI に聞く前に、自前の regex で伏せる ── 判断モデルを比べた結果と、本番への組み込み](https://raw.githubusercontent.com/EarthLinkNetwork/blog_public/main/images/pf-040/hero-ogp.png)

AI に送る文に、社外に出してはいけない情報が混じっていないか。それを確かめる役も AI に任せたい、と考えるのは自然です。

でも、確かめるために文をそのまま外の AI へ送れば、守りたい値はその時点で外に出ています。自社の AI サービス promptflow では、自前の regex（正規表現）で形で分かる値を先に伏せ、伏せた後の文だけを判断モデルに見せる形で、5 つのモデルを比べました。データは架空の日本語 120 件で、それぞれ 3 回ずつ判断しています。

## 結論

- **順番は regex が先、判断モデルが後です。** 判断モデルは、伏せた後の文から、形では分からない機密だけを足して拾います。
- **機密の見逃しは大きく減りました。** 機密を拾えた割合は、今の regex だけの 0.25 から、jev-preview を足すと 0.95 に。難しさのレベルの判断の完全一致は 0.25 から 1.00 になりました。
- **速さと費用は、毎回の要求に足せる範囲でした。** jev-preview は中央値 146 ms、1 日 2,000 回で月 $1.1〜1.4 です。
- **本番への組み込みは、記録だけを取る形にしました。** 今の判断は変えず、jev の答えを並べて記録する作りです。判断モデルの利用料の上限は月 $2 です。

## 本文（読了 約 7 分）

## 1. 確かめるために、先に送ってしまわない

promptflow には、要求のたびに走る、安くて速い判断が 2 つあります。

- **機密の判断**: Enterprise の契約向けの Security Filter です。メール・電話番号・カード番号・API キーなど 5 種類を regex で見つけて伏せてから、AI のサービスへ送ります。
- **難しさのレベルの判断**: Auto のモードで、どのレベル（L0〜L3）のモデルに任せるかを決めます。今の規則は、普通の会話なら「600 文字を超えたら L2、それ以外は L0」です。

regex は、形で分かる値なら見つけられます。でも「これは未公表の買収の話だ」という、文脈で決まる機密は見えません。そこで、後ろに判断モデルを足すことを考えました。判断モデルは、はい・いいえやレベルを、確率つきで速く安く答える専用のモデルです。

ただし、機密かどうかを決めるために、伏せる前の文を外の AI へ送るのでは本末転倒です。そこで、測る前に順番を決めました。自前の regex が先に伏せ、判断モデルには伏せた後の文だけを見せます。測った時も、本番と同じこの形です。伏せられるのは形で分かる値だけで、文脈の機密そのものは判断モデルに届きます。だから、どの会社の判断モデルを使うかも決めどころになります（6 節）。

![流れ図。1. 利用者の文（メール・電話番号・カード番号・API キーなどを含むことがある）→ 2. 自前の regex（自社のサーバーの中で、形で分かる値を伏せる。外へは何も送らない）→ 3. 伏せた後の文（値は置き換え済み。例 apiKey: '<PII_1>'）→ 4. 判断モデル（形では分からない機密や、難しさのレベルだけを答える）。下に「機密かどうかを決めるために、伏せる前の文を外の AI へ送れば、守りたい値がその時点で外へ出る。だから順番は regex が先」とある](https://raw.githubusercontent.com/EarthLinkNetwork/blog_public/main/images/pf-040/fig1.png)

## 2. 比べたもの

比べたのは、次の 5 つと、今の規則です。価格は入力 100 万トークンあたりの単価です。

| 候補 | 中身 | 価格（入力） |
|---|---|---|
| TypeSafe jev-latest / jev-preview | 判断モデル。答えたのは jev-1.13.0 と jev-1.14.0 | $0.042（出力は無料） |
| OpenAI Decisions API | 判断モデル（gpt-6-luna）。公開のベータ | $0.10（出力は課金なし） |
| gpt-5.4-nano / gpt-5.4-mini | 普通のチャットのモデルに、決まった形の JSON で答えさせる | nano $0.20・mini $0.75（出力は別に課金） |

データは、この試験のために作った架空の日本語 120 件です。機密の判断が 80 件（機密 40・機密でない 40）、難しさのレベルが 40 件（各レベル 10 件）。AI のレビュー役 2 つが別々に正解を付け、全件で合意しました。同じ 120 件を英語に機械翻訳した版でも測っています。

すべての候補を同じ問いで、日本語と英語それぞれ 3 回ずつ、東京から呼びました。呼び出しは合計 4,320 回、翻訳を含めた API の費用は約 $0.31 でした。

## 3. 機密の見逃しは 0.25 から 0.95 に

機密の判断は、本番と同じ形で数えています。regex が伏せた分はそのまま拾えたものとし、判断モデルは伏せた後の文から足すだけです。

![機密を拾えた割合の棒グラフ。今の regex だけ 0.25、regex + TypeSafe jev-preview 0.95、regex + TypeSafe jev-latest 0.87、regex + OpenAI Decisions API 0.92、regex + gpt-5.4-nano（JSON）0.88、regex + gpt-5.4-mini（JSON）1.00。架空の日本語の文 80 件・3 回の平均](https://raw.githubusercontent.com/EarthLinkNetwork/blog_public/main/images/pf-040/fig2.png)

regex だけでは、機密 40 件のうち、形で分かる 10 件しか拾えません。0.25 です。jev-preview を足すと 0.95、Decisions API で 0.92 になりました。gpt-5.4-mini は 1.00 で、1 件も見逃していません。ただし費用は jev の 10 倍を超え、速さは 5 倍ほど遅くなります（5 節）。

モデルだけの成績で比べないのには理由があります。API キーを含む文は、モデルに届く時には `apiKey: '<PII_1>'` のように、もう伏せてあります。これに「漏れていない」と答えるのは正しい答えです。だから、本番で見るべきなのは regex とモデルを合わせた数字です。

3 つの判断モデルがそろって見逃したものもありました。1 つは、買収先を名前でなく描写だけで書いたメモ。もう 1 つは「監査に報告していない、認証を飛ばす裏口がある」という文です。後者は、データの漏れというより、法令や規則への違反の話で、今回の問いの外でした。判断モデルは、小さな問いを組み合わせて使う作りなので、「報告していない違反が書かれているか」という問いを 2 つ目に足すのが正しい直し方です。

同じ jev でも、版で見逃しが変わりました。jev-latest（1.13）は、売上の計上の訂正、秘密保持の契約の下にある顧客の原価、未公表の弱点への対応方針の 3 件を見逃し、jev-preview（1.14）は 3 件とも拾いました。Decisions API だけが見逃したのは、出願前の特許の中身です。本番で版を固定する理由は、ここにもあります。版を替えると、拾える問題が入れ替わります。問題ごとに突き合わせて比べる方法は、「[AI のモデルを替える前に、問題ごとの合否を比べる](./PF-038.md)」に書きました。

jev-preview の確率は、止める・警告する・通すの 3 段階にも使えそうでした。確率 0.3 未満に機密は 1 件もなく、0.6 以上に機密でない文は 1 件もありませんでした。ただ、この境目は同じデータで当てたものなので、本番の文で取り直します。

Decisions API は、確率の分かれ方が違いました。0.1 未満と 0.8 以上でははっきり分かれるのに、0.1〜0.2 の帯に、機密の文への答えが 240 回中 12 回入っていました。「0.2 未満なら通す」と決めると、このモデルでは機密を通してしまいます。境目はモデルごと、版ごとに取り直す必要があります。

## 4. 難しさのレベルは 0.25 から 1.00 に

![難しさのレベル（L0〜L3）の判断で、4 つのレベルがぴたりと合った割合の棒グラフ。今の 600 文字の規則 0.25、TypeSafe jev-preview 1.00、TypeSafe jev-latest 1.00、OpenAI Decisions API 0.95、gpt-5.4-nano（JSON）0.79、gpt-5.4-mini（JSON）0.86。日本語の依頼はどれも 265 文字以下のため、今の規則はいつも L0 を返し、0.25 は偶然の当たりと同じ](https://raw.githubusercontent.com/EarthLinkNetwork/blog_public/main/images/pf-040/fig3.png)

jev は 2 つの版とも、40 件を 3 回とも全部当てました。Decisions API は、毎回同じ 2 件を 1 レベル低く答えて 0.95 です。どのモデルも、2 レベル以上ずれた答えはありませんでした。

今の規則の 0.25 は、データの側の事情でもあります。日本語の依頼は長くても 265 文字なので、規則はいつも L0 を返し、偶然の当たりと同じ数字になりました。長い文や、貼り付けた資料はまだ測っていません。

言語の差も出ました。TypeSafe の説明には、日本語・中国語・韓国語は英語ほど得意ではないとあります。でも、このデータの日本語では、jev-preview の見逃しは増えていません。逆に Decisions API は、英語にすると難しさの判断が 0.80 に下がりました。難しい依頼 5 件を、毎回 1 レベル低く答えています。言語の得意・不得意は、説明を読むより、自分のデータで測るのが確かです。

## 5. 速さ・費用・答えの揺れ

![速さと費用の表。今の regex は 1 ms 未満・$0、TypeSafe jev-preview 146 ms・月 $1.11、TypeSafe jev-latest 164 ms・$1.11、OpenAI Decisions API 222 ms・$1.67、gpt-5.4-nano（JSON）801 ms・$3.84、gpt-5.4-mini（JSON）772 ms・$14.19。難しさのレベルの判断では jev が月 $1.42、Decisions API が月 $1.95。jev の速さは、太平洋を越える通信（接続を張るだけで約 140 ms）を含む](https://raw.githubusercontent.com/EarthLinkNetwork/blog_public/main/images/pf-040/fig4.png)

jev のサーバーは海の向こうにあり、東京からは接続を張るだけで約 140 ms かかります。それを含めても、jev-preview の中央値は 146 ms でした。チャットのモデルは、大きさによらず 750〜800 ms ほどかかります。答えの文字を作る分の時間です。

費用は、1 日 2,000 回の判断で、jev が月 $1.1〜1.4、Decisions API が月 $1.7〜2.0 です。どちらも、毎回の要求に足して困る額ではありません。

単価だけで比べると、jev は Decisions API の 2.4 分の 1 です。それでも費用の差が 1.5 倍ほどに縮むのは、同じ日本語の文が、jev では 459 トークン、Decisions API では 278 トークンに数えられるからです。費用の見積もりは、文字数でなく、数えられたトークンの数で出します。

速さと費用より気をつけたいのが、答えの揺れです。同じ入力を 3 回送ると、gpt-5.4-nano は 80 件中 14 件で答えが変わりました。jev-preview は 1 件です。機密の判断で、同じ文の答えが回ごとに変わるのは困ります。

Decisions API は、ベータらしい面も見せました。720 回のうち 2 回、成功を表す HTTP 200 を返しながら、中身が空でした。速さの 95% 点が 3.4 秒になった回もあります。組み込むなら、時間切れと、失敗した時にどちらへ倒すかを、呼ぶ場所ごとに決めておく必要があります。

## 6. 本番への組み込みは、今の判断を変えずに記録だけ取る形にした

本番への組み込みは、難しさのレベルの判断から始めました。いきなり判断を切り替えると、L2・L3 の高いモデルに回る要求が増え、費用が動きます。それに、測ったのは架空のデータです。そこで、今の規則のまま判断を続け、同じ要求について jev ならどう答えたかを、記録だけする形にしました。

- **モデルは jev-preview を選び、版を固定しました。** 送るのは jev-1.14.0 です。測った時、jev-latest という名前は、新しい版が出た後も古い 1.13 を返していました。
- **送るのは、regex で伏せた後の文だけです。** 文はこちらに保存しません。ただし regex が伏せるのは、形で分かる 5 種類の値だけです。氏名・会社名や、未公表の買収のような文脈の機密は、伏せられないまま判断モデルに届きます。会社の組織に属する利用者や、所属が分からない利用者の要求は、送らずに飛ばします。
- **3 秒で打ち切り、失敗しても応答の中身は変えません。** 判断は利用者には見えません。ただ、待ち時間は最大で 3 秒あまり延びることがあり、その分も記録で測ります。
- **判断モデルの利用料に上限を付けました。** 本番は 1 日 $0.056、ほかの環境は $0.001 です。3 つの環境を合わせても、31 日の月で $1.80 以下に収まり、月 $2 の範囲に入ります。
- **機能の切り替えスイッチで、いつでも止められます。**

その後、同じ 1 回の判断に「依頼の種類（文章・Office・画像・動画・音声）」の問いも足しました。jev の種類の答えを本番の判断に使う経路は、スイッチを切った状態で入れてあります。入れるのは、jev が答えた判断が 5,000 件を超え、今の判断との一致の割合を見せて、承認を受けてからです。ここまでの変更は、promptflow の版 promptflow-web-v91 に入っています。

### 切り替える前に、記録から何を見るか

記録が 14 日以上、かつ jev が答えた判断が 5,000 件以上たまったら集計します。見るのは次の 5 つです。

- **レベルの分かれ方と、今の規則との一致**: L0〜L3 がどう分かれ、今の規則とどこで食い違うか。
- **足される待ち時間**: 中央値と 95% 点、時間切れと失敗の割合。
- **かかった費用**: 1 日あたりの額と、前もって見積もった額との比。
- **切り替えた時の費用の増え方**: 高いレベルのモデルに回る分の増加の見込み。
- **記録の偏り**: 会社の組織などで飛ばした要求が 30% を超えたら、結論を出さずに、送る相手の決め方を見直します。

### TypeSafe を選んだことで増えるもの

判断モデルの会社をどこにするかは、数字だけでは決まりません。OpenAI はもともと文を送っている先の 1 つなので、Decisions API なら送る先の会社は増えません。TypeSafe を選ぶと、伏せた後の文を受け取る米国の会社が 1 つ増えます。伏せた後の文にも、氏名や文脈の機密は残っています。120 件の架空データなので、判断モデルどうしの数ポイントの差は誤差の範囲です。はっきりしているのは、今の規則とどの判断モデルの間にも大きな差があることです。選んだのは jev-preview です。判断モデルの間で差がはっきり出たのは、速さ（中央値 146 ms 対 222 ms）と、Decisions API がまだベータで空の答えを返したことでした。形で分かる値を伏せてから送る作りは、どちらの会社を選んでも変えません。

## まとめ

- 機密かどうかを確かめるために、伏せる前の文を外へ送らない。自前の regex で先に伏せてから、判断モデルに聞きます。
- jev-preview を後ろに 1 つ足すだけで、機密を拾えた割合は 0.25 から 0.95 に、難しさのレベルの判断は 0.25 から 1.00 になりました。費用は月に 1〜2 ドルです。
- 本番への組み込みは、今の判断を変えずに答えを記録する形にしました。本番の文での一致の割合は、この記録で測る作りです。

## 用語

- **判断モデル**: はい・いいえや、決まったレベルのどれかを、確率つきで答える専用の AI のモデル。文章は作らないので、速くて安い。
- **regex（正規表現）**: 文字の並びの形で値を見つける書き方。メールアドレスやカード番号のように形が決まった値に向く。
- **JSON**: 項目の名前と値を決まった形で並べる、プログラムが読みやすい書き方。
- **トークン**: AI が文を数える単位。料金はこの数で決まり、同じ文でもモデルによって数え方が違う。
- **伏せる（マスク）**: 見つけた値を `<PII_1>` のような置き換えの文字列に入れ替えること。元の値は外へ送らない。
- **機密を拾えた割合（recall）**: 本当に機密の文のうち、機密だと判断できた割合。1.00 なら見逃しがない。
- **完全一致**: 難しさのレベル（L0〜L3）が、正解のレベルとぴたりと同じだった割合。
- **中央値（p50）**: 測った時間を短い順に並べた時の真ん中の値。95% 点（p95）は、95% がその時間以内に収まる値。
- **記録だけの試験運転（shadow）**: 本番の判断・応答・課金は変えず、同じ入力を新しい仕組みにも送って、答えを記録だけすること。利用者には見えない。
